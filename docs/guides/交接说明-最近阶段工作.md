## 二、这次交接前我做了什么（按时间）

### 1. 正式 UI 落地（FastAPI + Vue3）
- 后端 `server/main.py` 把 `agent_core` 包装成 REST + SSE API，核心逻辑零改动
- 前端 `web/`：Vue3 + Vite + TS + Element Plus + ECharts，两页——**总览看板** + **智能对话**
- 看板：KPI 指标栏（低评分率/延迟率/样本/平均评分 + 迷你走势）+ 3 张图表（客户州条形图 / 支付方式环形图 / 月度趋势面积图）
- 对话：SSE 流式（intent → running → result/step → answer → done）+ 意图路由 + 结果卡片（归因优先级表 + OR 森林图 / 统计方法表 / 查询表格 + SQL）

### 2. 全量 MySQL 数据接入
- 用 `scripts/import_mart_to_mysql.py` 把三张 Mart 全量导入 `olist_ecommerce` 库（订单 99,441 / 订单-卖家 100,010 / 商品项 112,650）
- `.env` 设 `USE_MYSQL=1` 即切换全量数据源；默认无此配置走演示样本 CSV

### 3. 会话历史数据库化（重大架构变更）
- **之前**：会话历史存在浏览器 localStorage（约 5MB 上限，归因大结果被迫降级存摘要，换设备即丢）
- **现在**：存在 MySQL `chat_session` / `chat_message` 两张表（`server/session_store.py`），结果整份入库（LONGTEXT），跨设备保留
- 新增 REST：`/api/sessions`（CRUD）+ `/api/sessions/{id}/messages`（读写）
- **坑**：`SessionStore` 早期用全局单例共享连接，并发下会 `struct.error` 500；已改为每次方法独立开/关连接（contextmanager），已修复

### 4. 看板/对话高质感重构（多轮，按设计评审方案）
- 图表美学：条形图加浅灰底槽 + 胶囊圆角 + 青蓝渐变 + Top3 徽章；环形图加粗环体 + 中心大数字 + 2×2 卡片化图例（弃单行横排）；趋势图去常驻数据点 + 平滑曲线 + 深色 tooltip
- 对话卡片：去重复纯文本，改加粗业务洞察结论；卡片底部「继续追问」带图标快捷胶囊；用户头像从文字改为浅色矢量人像（lucide）
- 侧边栏：会话管理（新建/切换/删除 + 消息数）、Lucide 矢量图标、AI 头像体系
- 布局：输入框改为绝对定位悬浮（不挤压消息可视区）

### 5. 偏难怪题批量测试（新增 `tests/edge_case_probe.py`）
直接调后端 `/api/chat`（SSE）批量测 20 题，抓到并修复 2 个真实 bug：
- **金额筛选静默降级**："运费 100 块以上的订单平均评分"原来无视筛选返回整体 4.16，现返回筛选后 3.66（`query_analysis.py` 补金额筛选正则）
- **"差评"漏判归因**："帮我分析哪些因素和差评有关"原来误判 other，现正确判 attribution（`intent.py` LOWSCORE_THEME 补"差评"）

### 6. 其他关键修复（详见 TEST_LOG）
- **年份期间对比**：支持"2020 相比 2019 低评分率变化"→ 确定性算出差值；数据缺失年份时明确提示，绝不静默返回单值
- **静默降级根治**：完整性检测词表扩充（相比/同比/变化/去年…），识别不完整时走 LLM 兜底而非瞎答
- **历史会话完整恢复**：query 等小结果整份入库，恢复历史可还原完整表格（不再只有摘要）

## 三、怎么跑

```powershell
# 1. 后端 + 前端（生产单端口，需已 build）
uv run uvicorn server.main:app --port 8000    # http://localhost:8000

# 2. 前端开发模式（热更新，proxy /api → :8000）
cd web
npm install
npm run dev                                    # http://localhost:5173

# 3. 构建前端
cd web && npm run build                        # 产物由后端自动托管
```

前置条件：
- MySQL 服务在跑，`olist_ecommerce` 库存在（含三张 Mart + 自动建会话表）
- `.env` 配好 `DB_*` 和 `DEEPSEEK_API_KEY`（示例见 `.env.example`，.env 已 gitignore）

## 五、已知坑与注意

1. **MySQL 服务必须开着**，否则看板/对话 500——这是最容易踩的坑
2. **浏览器访问用 `http://localhost:5173`**（Vite 绑定 IPv6），别用 `127.0.0.1:5173`
3. **旧会话不自动补全**：会话历史数据库化之前存的归因会话 result 为空，重问一遍才完整
4. **归因较慢**：全量归因 30–90 秒，后端有 24h 缓存；前端 axios timeout 300s
5. **Playwright/浏览器自动化对 Element Plus v-model 有盲区**：`fill` 不触发发送，用 CUA 真实按键；但真实用户手输正常
6. **`.env` 不要提交**（已 gitignore）；`.env.example` 是模板
