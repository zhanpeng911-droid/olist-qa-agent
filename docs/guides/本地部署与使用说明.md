# Olist 业务数据分析助手：本地部署与使用

## 当前数据状态

`data/sample/` 包含订单级、商品项级和订单—卖家级三张分析宽表的截取样本。当前每张文件均为 1,000 行，仅用于检查功能与分析流程，不能代表全量业务结论。

程序默认读取演示样本，并在内存中补齐月份、延迟分档和线路等兼容字段，不会修改原始 CSV。商品项分析与订单评价连接时，低评分率固定按去重 `order_id` 计算，避免一单多商品重复计数。

## 首次安装

在项目根目录执行 `uv sync`；进入 `web` 目录执行 `npm install` 和 `npm run build`，分别建立 Python 隔离环境并生成前端构建产物。

## 日常启动

双击 `启动Agent.bat`，浏览器会打开 `http://127.0.0.1:8000`。数据源由根目录 `.env` 中的 `USE_MYSQL` 固定：`USE_MYSQL=1` 读取 MySQL；不设置时读取截取样本。

可直接提问：`请对低评分进行归因分析`、`请对延迟进行归因分析`或`哪些因素与交接超期有关？`。页面会先逐变量展示检验方法、原始p值、FDR校正p值、效应量及95%置信区间；仅保留校正后显著且置信区间排除无效值的变量，并按预设规则处理共线性；随后运行包含固定控制变量、采用HC3稳健标准误的多变量Logistic模型。只有控制其他因素后仍显著且置信区间有效的变量才展示具体分布或对象明细。

商品/品类下钻不再只是排名：程序会先按订单去重，再逐个检验“订单是否包含该品类或商品”与低评分的关联，并使用FDR-BH校正多重比较。页面分别列出已显著可关注对象、描述性风险较高但尚未显著的待验证对象，以及因样本不足暂时无法判断的情况。

如果只想核对某个特征，可问：`延迟在低评分分析中使用了什么检验方法以及p值？`、`线路与低评分使用什么检验方法，p值是多少？`。系统会按变量类型选择固定方法并列出p值和效应量。

## 两种数据源

1. 演示样本（截取数据）：读取三张分析宽表的截取样本，用于功能检查与回归测试；2. 完整业务数据库（MySQL）：读取三张全量分析宽表，用于正式分析。旧人工模拟数据已删除，避免维护两套作用重复的数据。

## 切换到 MySQL

正式分析应使用 MySQL。把 `.env.example` 复制为 `.env`，填写 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`、`DB_ITEM_TABLE`，并设置 `USE_MYSQL=1`。连接信息只保存在本机 `.env`；该文件已被 Git 忽略。

默认连接参数为：`127.0.0.1:3306`、用户 `root`、数据库 `olist_ecommerce`。商品项 Mart 表属于 Olist 数据库内部对象，由程序自动使用，不需要在界面单独配置。

正式使用时，分析宽表应通过只读账号访问。会话功能还需要在同一数据库中创建并读写 `chat_session`、`chat_message` 两张应用表；程序首次启动会自动创建它们。

如果三张 Mart 表已经存在，不要运行 `scripts/import_mart_to_mysql.py`。该脚本仅用于从 CSV 重建表，并会在显式传入 `--replace` 后删除同名表。

如果继续使用 CSV，可用同名全量文件替换 `data/sample/` 中的三份 1,000 行样本：`mart_order_delivery.csv`、`mart_order_item_delivery.csv`、`mart_order_seller_delivery.csv`。也可以通过 `.env` 中的 `PROJECT_DATA_DIR` 指向其他只读数据目录。

## 功能边界

- 关联因素分析基于观察性数据，结果不能直接解释为因果；
- Mart 表没有评价正文，不能判断破损、错发、客服态度等文本原因；
- 当前自动化关联因素分析只支持交接超期、最终延迟和低评分三个目标；交接超期只使用事前基础属性，最终延迟使用基础属性与交接超期，低评分再允许使用最终延迟；其他变量可做双变量检验，但不能作为自动化归因目标；
- 未配置 DeepSeek API 密钥时，确定性的三目标关联因素分析、统计检验和补充验证仍可运行；规则无法可靠解析的开放式问题不能调用大模型；
- 多变量回归在样本过小、类别稀疏或完全分离时会降级，不强行报告不稳定的调整 OR。
- 完整数据库模式会自动运行受控Logistic模型，但按分析宽表串行读取必要字段；分类检验由SQL聚合，连续变量筛选每次最多读取两列，不会将三张全量宽表同时载入内存；
- 无论结果是否显著，系统均不自动生成责任方、治理动作、监控指标或A/B方案。
