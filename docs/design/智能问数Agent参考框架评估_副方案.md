# 数据分析 Agent 参考框架评估（副方案）

> 评估对象：一张"数据分析Agent架构/成熟度模型"参考图（含 L1-L4 成熟度模型 + 双核心架构 + 置信度系统）
> 评估目标：该框架能否满足 Olist 电商履约与评分分析业务的问数 Agent 需求
> 关联主方案：《智能问数Agent方案设计.md》v2.3
> 版本：v1.0

---

## 0. 参考框架速览

参考框架包含三部分：

1. **传统工具 vs 数据智能体**对比（命令-执行 → 对话-探索）
2. **数据智能体成熟度模型 L1-L4**：
   - L1 响应式执行（Text-to-SQL 取数）
   - L2 理解式洞察（多维分析 / 异常检测 / 归因诊断）
   - L3 建议式决策（预测 / 策略推荐 / 多方案推演）
   - L4 自主式决策（闭环执行与持续优化）
3. **双核心架构**：数据问答 Agent 体系 + 深度分析 Agent 体系 + Multi-Agent 记忆系统 + Confidence System（投票 / 在线评审 / 置信度推理评分），贯穿 Human-in-the-loop。

---

## 1. 核心结论（先说答案）

> **能满足我们业务，且方向高度正确；但整体明显偏重。** 我们业务的核心诉求落在 **L1-L2**（问数取数 + 归因诊断），参考框架的精华（分层演进理念、问答/深度分析两体系、记忆与置信度思想、Human-in-the-loop）都应采纳；但其 **L3-L4 能力、多 Agent 团队、知识图谱、投票评审机制** 对当前规模属于冗余，应裁剪后渐进落地。

---

## 2. 我们业务在成熟度模型的哪一层？

| 业务需求 | 对应成熟度 | 说明 |
|---|---|---|
| 中文问数取数（延迟率、低评分率、GMV 等） | **L1 响应式执行** | 我们主方案的问数模式，Text-to-SQL 取数 |
| 履约 / 评分 / 地区 / 品类 / 卖家归因 | **L2 理解式洞察** | 我们业务的**核心诉求**——归因诊断 |
| "延迟与低评分是否相关、控制变量后是否显著" | L2 增强 | 主方案 4.5 统计检验工具注入即此 |
| "如何改善评分"（策略建议） | **L3 建议式决策** | 可作可选增强，非必须 |
| 自动闭环运营（广告投放 / 智能补货） | **L4 自主式决策** | **超出我们业务边界**，不需要 |

**判定**：我们业务当前定位 **L1-L2**，重点是 L2 归因诊断。L3 可选，L4 明确不做。

---

## 3. 双核心架构逐模块评估

| 参考框架模块 | 适用性 | 评估 |
|---|---|---|
| **数据问答 Agent 体系**（意图→理解→知识增强→NL2SQL→执行→纠错→记忆） | ✅ **完全适用** | 与我们主方案高度重合，可直接对标落地 |
| **深度分析 Agent 体系**（Planner + PlanAct Loop + DeepAnalyst 团队：规划/代码/复盘/检查 Agent） | 🟡 **部分适用，需裁剪** | 我们确有归因诊断需求（L2），该体系能支撑；但"规划/代码/复盘/检查"4 个专职 agent 对单库小规模偏重，可裁剪为"单 agent + 反思（复盘/检查）+ 统计工具" |
| **Multi-Agent 记忆系统**（上下文记忆 / 企业知识库 / 行为知识库 / 云存储） | 🟡 **简化适用** | 上下文记忆（多轮）有用；"企业知识库/知识图谱/向量检索"对单项目过重，用我们的**语义字典 + 口径文档 + 术语表**即可覆盖 |
| **Confidence System**（投票 / 在线评审 / 置信度推理评分） | 🟡 **有吸引力，但可简化** | 其价值（防幻觉、可信度）我们已用"结构化 SQL + 禁 join + 对账 + 人工确认"实现；投票/多评审 agent 是冗余防御，可在**关键结论**上用"check 节点 / 双模型交叉"轻量替代 |
| **Human-in-the-loop** | ✅ **已一致** | 我们已采用（清洗确认、结果可对账） |

---

## 4. 与主方案的映射：取其精华、裁其冗余

参考框架给我们**最值得采纳的 5 点**：

| 借鉴点 | 如何映射到主方案 |
|---|---|
| ① 成熟度分层演进（L1→L2 渐进） | 主方案里程碑已天然分层（M1 问数 → M2 反思 → 统计检验） |
| ② 数据问答体系 = 我们的问数模式 | 已实现，无需改动 |
| ③ 深度分析的"复盘/检查"思想 | 主方案 ReAct 的"反思"节点即此，可强化为独立"检查"步骤 |
| ④ 记忆系统 → 多轮上下文 + 语义字典 | 多轮追问（M2）已规划；知识库即我们的口径文档 |
| ⑤ Confidence → 关键结论加置信度/校验 | 可加"关键数字复核 + 附 SQL 可对账"，不必上投票 agent |

**明确裁剪（不适合我们）**：
- L4 自主式决策（超出业务边界）
- DeepAnalyst 多 Agent 专职团队（单库小规模过重）
- 知识图谱 / 向量检索 / 多模态知识库（单项目冗余）
- 投票 + 在线评审多 agent（用轻量校验替代）

---

## 5. 结论：能否满足我们业务？

**能满足，但方式是以"取其分层与问答/深度分析精华 + 裁剪重组件"来满足，而不是照搬全套。**

- ✅ 满足：L1 问数 + L2 归因诊断（我们业务核心）
- 🟡 可选：L3 策略建议、置信度校验（按需增强）
- ❌ 不做：L4 自主决策、多 Agent 团队、知识图谱、投票评审（与业务边界和规模不符）

参考框架的核心价值在于**帮我们确认了演进方向和能力分层**——我们主方案（问数 + 统计 + 清洗）本质上已经踩在它的 L1-L2 轨道上，且已内嵌了它强调的 Human-in-the-loop 与可对账（可信）理念。因此**主方案无需推翻，只需按此框架做增量补充**。

---

## 6. 建议的增量补充（可选，不强制）

若想进一步贴近参考框架，可在主方案基础上加：

1. **复盘/检查独立化**：把 ReAct 反思拆成明确的"生成 → 检查 → 修正"两段式（对应 DeepAnalyst 的检查/复盘思想）。
2. **关键结论置信度标注**：对归因类结论标注"证据强度 + 是否经统计检验 + 附 SQL"，对齐 Confidence 思想（轻量版）。
3. **多轮上下文持久化**：会话记忆落地（对应对应参考框架的上下文记忆）。

这些均属**增强项**，不影响 M1 核心，建议在 M2 之后按需选用。
