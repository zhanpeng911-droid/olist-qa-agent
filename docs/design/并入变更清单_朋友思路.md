## 3. 变更内容详述（待审批）

### A. 字段名标准化
- 主方案、`semantics/metrics_dict.yaml`、`agent_core/data_provider.py`、`data/sample/` 与 `tests/*` 中的字段名按第 2 节映射表统一。
- 语义字典补充新字段：`has_review_record`、`delivery_variance_days`、`order_month`（`DATE_FORMAT(order_purchase_timestamp,'%Y-%m')`）、`route`。
- 执行后重跑 `pytest` 确认 10/10 仍通过（样例数据字段名同步改）。

### B. 新增「L2 归因诊断」章节（主方案新增 4.8）
- 定位：L1 问数之上，完成"多维下钻 → 异常定位 → 统计验证 → 治理优先级 → 改善建议"闭环。
- 归因口径：观察数据风险因素诊断，**禁止因果措辞**（"导致/造成"），只能"显著相关/控制现有变量后关联仍存在"。
- 两表职责：`mart_order_delivery`（订单级归因主表）+ `mart_order_seller_delivery`（卖家/线路归因表）；第一版**不自由连接两表**，分别出证据、结果层汇总。
- 执行流程：解析生成计划 → 建基准 → 扫描候选因素 → 选统计方法 → 证据分级 → 映射改善建议。

### C. 统计工具扩展（主方案 4.5 升级）
- 由 3 个工具扩展为完整 L2 工具集：
  `build_baseline` / `screen_factors` / `excess_low_score` / `categorical_test`(卡方/Fisher+RR/OR+CI) / `distribution_test`(Mann-Whitney U+效应量) / `correlation_test`(Spearman) / `trend_test`(趋势OR+p值) / `logistic_model`(调整OR+HC3稳健SE) / `rank_priorities`(P0/P1/P2) / `recommend_actions`。
- 贡献拆解指标：样本量、低评分率、基准率、**Lift**、**超额低评分数**（`样本量×max(组内率-基准率,0)`）。
- 排序原则：**问题规模 × 风险增幅 × 可干预性**，不只凭 p 值；`min_group_sample=100` 过滤小样本。
- 多重检验校正：Holm / Benjamini-Hochberg。
- 模型约束：延迟相关高相关变量不共入一模型（拆"是否延迟/延迟程度"两模型）；订单级与单卖家订单级各建一模型。

### D. 建议规则库（主方案新增 4.9 + config 文件）
- 新增 `config/recommendation_rules.yml`：已验证风险因素 → 责任方 / 动作 / 监控指标 / 验证方式。
- 建议不由 LLM 自由发挥，由规则库映射 + 模型组织语言。
- 示例规则（来自朋友文档）：延迟1-3天→客服/物流主动通知+更新ETA；延迟4天+→人工介入+补偿；高规模跨州线路→线路SLA+P90预警；卖家晚交运→临期提醒+分层整改；多商品/多卖家→分包进度展示；品类偏高→下钻SKU+评价文本。

### E. 语义字典 guards 补强
- 新增：低评分口径固定 `review_score<=3`；分析分母 `has_review_record=1`。
- 新增：卖家/线路分析默认 `is_multi_seller_order=0`，多卖家订单禁止 `COUNT(*)` 重复计算评价。
- 新增：`min_group_sample: 100`。
- 新增：评价正文缺失边界（无 `review_comment_message` 时禁止臆测破损/错发/客服/退款原因）。

### F. System Prompt 约束 + 回答结构模板
- `loop.py` 的 system prompt 补充 10 条约束（低评分口径、先基准后分组、两表分工、去重、显著≠重要、禁因果、不臆测文本原因、建议含责任方/指标/验证、只读白名单、数据不足说明缺口）。
- 新增回答结构模板（固定 5 段）：总体判断 / 归因证据表 / 改善建议表 / 不能下结论部分 / 数据来源。

### G. 里程碑重排（对齐朋友 M1-M4）
- **M1（已完成，维持现状）**：L1 问数（语义字典 + 工具层 + ReAct + 对账测试）——已交付，不重做。
- **M2（L2 描述性归因）**：候选因素扫描、Lift/超额低评分、规模×风险排序、小样本过滤、输出问题对象。
- **M3（统计验证）**：卡方/Fisher/MWU/Spearman/趋势检验、订单级+单卖家 Logistic、多重校正、证据分级。
- **M4（建议与评测）**：建议规则库、20-30 个标准问题评测、数字准确率/安全/因果越界/建议可执行性检查。
- 注：原主方案 4.7（置信度标注+上下文持久化）保留为贯穿项，在 M2/M3 中落地。

### H. 技术选型补充
- 当前（已用）：uv / Python / SQLite样例 / openai(DeepSeek) / pyyaml / pytest / python-dotenv。
- 后续（M2/M3 接入）：`scipy`、`statsmodels`（HC3 稳健标准误）、`SQLAlchemy`+`PyMySQL`（只读连 MySQL）、`pydantic`（工具入参出参约束）；FastAPI/Streamlit 为展示层可选。

### I. 验收标准（并入朋友 8 条）
指标正确性（与人工 SQL 一致）、粒度安全（多卖家不重复/两表不失控连接）、方法匹配（按变量类型选检验+效应量）、结论可追溯（每数字可溯源）、边界控制（不因果/不臆测文本）、建议质量（责任方+动作+指标+验证）、稳定性（重复问结果一致）、安全性（只读/禁DML-DDL/限表限行限时）。
