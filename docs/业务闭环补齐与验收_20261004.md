# 业务闭环补齐与验收（2026-10-04）

## 目标

本轮补齐三个已识别的业务缺口：动态取数不能完整交付超过5,000行的明细；AI发布版缺少页面恢复入口；旧正式库的一个卖家城市转义错误会与正确源CSV冲突。不是新增自动归因或经营策略功能，也不是将数据库任意写权限交给模型。

## 功能与操作

### 1. 轻量取数与完整交付分离

在AI数据助手提问，由现有DeepSeek检查schema、按skill生成并执行只读SQL。轻量结果仍最多5,000行、页面预览50行；超过上限明确标记截断，不能将它视为完整明细。

需要完整结果时，检查“查看原始SQL”，点击“完整导出原始SQL结果”并确认。后台按当前发布数据版本执行这条SQL，不使用工具自动附加的预览LIMIT；但用户主动要求的LIMIT、OFFSET、筛选仍保留。完成后显示实际行数与完整CSV链接。

完整导出不再调用模型、不将全量数据发送给DeepSeek、不全量载入pandas；使用一致性只读事务与流式游标，精确保留DECIMAL和日期，输出UTF-8 BOM CSV，并记录文件SHA-256和数据版本。CSV公式前缀加单引号保护。当前保护预算为200万行、1GiB、5分钟、最多100个唯一列名，另有执行计划成本上限。任一超限或服务中断都明确失败，未完成文件不可下载。

注意：完整导出是重新执行，不保证与较早的轻量预览属于同一版本；新增版本期间的构建/维护与导出共用互斥锁。它不是无限量导出服务。

### 2. AI发布版恢复上一版

选择“已发布”的AI工程任务，点击“预览恢复上一版”；程序检查该任务仍是当前版本、备份包含完整三层且质量门无FAIL。查看恢复影响后点击“确认恢复上一版”。

确认时再核验当前版、备份版和计划指纹，以单条原子RENAME恢复九张Raw、四张Staging、三张Mart及版本元数据。被替换的当前版本保留在恢复库，不删除。非当前任务、发布后被直接修改的数据、变化备份、过期计划、重复回滚和首次空库没有完整前版都拒绝覆盖。

原子数据库切换与本地审计文件不是同一个事务。如果恢复后审计写入失败，程序以当前库和恢复库的校验和核验是否已提交；无证据时保留待核验状态，不误报旧版本仍发布，也不自动再次覆盖。

### 3. 源文件可证明的旧文本修复

数据工程页面使用原始九表源目录，点击“预览源字符差异”。仅接受卖家城市中源文件字面量反斜杠+r被旧导入器解为回车的差异；要求卖家ID、邮编、州和完整键集合一致。其他变化拒绝，不作为通用upsert入口。

预览包含源SHA-256、旧/新值、各表影响行数及基线指纹。确认后保存不可变源副本、克隆完整三层，仅修正Raw卖家与对应卖家Mart、商品项Mart的城市；36项质量门和正式基线复核通过才原子发布。保留完整前版，不改订单金额、状态、关联键、源文件或上游快照水位。

本机历史差异对应卖家`cf1313c6e2c01c2f4b014f97db4bcd2b`：Raw一行、卖家Mart五行、商品项Mart五行，共11个城市值。修复以源CSV为准，不能删除整列、放宽所有文本容差，或用当前时间伪造源快照。

## 复测

启动MySQL，在v2目录串行执行，不与页面构建/恢复同时运行：

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
$env:OLIST_TEST_MYSQL='1'
.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider --basetemp artifacts/business_gaps_final_tmp --junitxml artifacts/business_gaps_final_u.xml
# 需明确许可；消耗真实DeepSeek API额度
.venv\Scripts\python.exe scripts\run_llm_eval.py --allow-model-data --repeat 3 --engineering --business-gaps
```

M发送问题、skill、schema、SQL、摘要和许可范围内最多50行预览，不发送密码/API Key或完整导出。独立参照不提供给模型。首次/增量/重叠与恢复的写入只发生在隔离测试库，正式库只读复核。

历史转义修复的隔离脚本只适用于旧差异尚存在时。正式库修复后不应为复测制造错误，应保留已有4项完整验收证据。显式生产修复脚本需`--confirm-production`，不要将它混入普通无副作用MU测试。

## 保留边界

以上覆盖Olist合约内、本机单用户的导入—建模—报表—动态取数—完整交付—恢复闭环，不等于任意业务输入和企业级上线均已验证。源数据仍缺少可靠更新时间、删除事件及部分稳定事件ID；质量门不能自动证明所有模型改写的业务表达式正确。没有多用户权限/审批、持久调度队列或全部工件自动保留政策。现有测试库、输入快照、备份、恢复库和旧代码备份保留，继续占用磁盘。
