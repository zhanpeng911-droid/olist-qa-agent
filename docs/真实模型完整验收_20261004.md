## 验收范围与状态

本轮已取得向DeepSeek发送测试指令、表结构、skill、SQL、校验摘要及每次最多50行预览的明确许可。使用.env原有的`deepseek-v4-flash`，不替换模型、不将取数验收的独立参照SQL提供给模型，也不使用脚本响应代替模型。工程允许模型读取skill配套的建模参考SQL，但必须通过execute_sql实际提交，读取参考本身不算执行。

**本轮覆盖场景的完整验收已完成，最终复测全部通过。** 取数仅对正式库只读；工程确认发布仅针对`olist_llm_*`和已有的`olist_accept_88e89f01`隔离库。密码、API key不发送。原始数据逐行解析与Raw安全合并由确定性工具负责；LLM规划并通过工具实际提交Staging/Mart SQL。

## 验证方法

取数使用25个真实问题，覆盖指标分母、多条件筛选、商品项归属、Raw回探、多评价去重、窗口函数、空时间段、明细截断、业务澄清、字段缺失、越权拒绝和SQL字面量。实际查询结果逐项对照独立MySQL参照，核验用户指定列名、订单粒度、NULL、金额、比率和下载CSV。`--repeat 3`顺序执行三轮，而不是每题紧接着重复三次。

工程先验证30笔首次导入、扩展到60笔、60笔重叠快照，随后将45,430笔历史订单的隔离库扩展到99,441笔全周期订单。要求模型实际提交建模SQL、36项质量门无FAIL、发布前不自动切换、未确认时拒绝发布、确认后16张表行数与金额一致。另按主键排序流式比较三张Mart的全部基线字段，不把全量数据装入pandas，也不发送给模型。

网页验证实际提交自然语言需求、查看本地结果与SQL、下载CSV，并检查控制台错误。代码回归、固定任务验收、模型验收和最终内容对账分别记录，不能相互替代。[OpenAI Docs评估指南](https://developers.openai.com/api/docs/guides/evaluation-best-practices)用于指导工具选择、参数正确性与最终结果分别评分。

## 首轮发现与修正

| 问题 | 处理 |
|---|---|
| 模型为全量明细自动发起大量OFFSET分片，超过单轮工具上限 | skill和工具说明明确5,000行上限、截断必须告知，禁止自动分片绕过；保留原权限和资源上限 |
| 增量建模已完成并通过质量门，仍在回答阶段超过累计token预算 | 已成功执行的SQL回执移除重复SQL正文，已使用参考保留摘要/指纹；完整原始历史及实际提交SQL仍保留本地；质量通过后结束重复对账 |
| 超预算的最后一次API响应未计入本地usage | 先记录本次响应、轮次及usage再检查预算，确保费用审计不遗漏已发生调用 |
| 指定seller别名但CSV仍输出seller_id | 增加提交前逐列核对及AS别名要求，不放宽输出契约 |
| 对已明确的“全部订单、订单级商品金额”反复澄清 | 明确用户范围优先于默认GMV口径，列名gmv不改变已经明确的全部状态范围 |
| 拒绝删除后擅自运行替代统计 | 纯越权请求结束，不执行用户未选择的替代分析 |
| 已诚实说明字段不存在，却被测试脚本判失败 | 允许完成态或待输入态的明确缺失说明；需要选择的定义仍必须暂停，越权请求仍不得执行查询 |
| 原始评价已回探，最终评分正确复用Staging，但要求Raw必须在同一SQL中 | 评价标准改为完整执行轨迹确实回探Raw且最终结果对账正确；不要求不必要的重复JOIN |

## 旧库基准的一个源数据差异

初次直接逐字段比较旧正式库，订单Mart一致，另外两张Mart的seller_city各有5行不同。定位至卖家`cf1313c6e2c01c2f4b014f97db4bcd2b`：原始CSV城市名中包含字面量反斜杠+r，旧Raw将其解释成实际回车；新工具的参数化导入保留原始字符。因此这是旧库导入保真问题，不是模型建模错误。

独立对账以原始`olist_sellers_dataset.csv`为该字段的参照，源文件SHA-256为`1f643d2b950373b85735e7794b20986f528d7a000432e7c6f9bcbb44d0846a0e`。只接受可准确追溯的“字面量反斜杠+r→回车”旧基准差异，其他城市、键或字段差异仍失败；不删除seller_city列，不改目标数据，也不泛化文本归一化。两目标库全部3,095条Raw卖家记录的四个原始字段均与CSV一致，三张Mart随后完整匹配源校准后的预期。

初始差异报告`model_mart_comparison_87c195a9.json`和定位报告`model_mart_differences_10cd241a.json`保留。正式库没有改动。后续若把同一全量CSV直接“仅追加”到现有正式库，该旧字符冲突会按合并政策拒绝；需审核后选择可信的较新快照更新，或在新库构建后确认切换，不能为了通过导入静默覆盖。
